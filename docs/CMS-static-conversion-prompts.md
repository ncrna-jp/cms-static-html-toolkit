# CMS静的HTML化で使うプロンプト集

次回、Codexなどに依頼するときのためのプロンプト例です。必要に応じてドメイン名やCMS名だけ置き換えて使います。

## 1. 全体戦略を作らせる

```text
私は <サイトURL> の管理者で、CMSバックエンドにもアクセスできます。
このサイトを、できるだけリンク切れ・画像漏れ・CSS崩れ・外部読み込み依存が起きないように、静的HTML化したいです。

対象CMS:
- CMS名またはフレームワーク名

条件:
- バックアップは取得済み
- RSS/Atomは不要
- 問い合わせフォームやログインなど、静的化後に動かない機能は削除または無効化したい
- 外部サイトへのリンクはそのまま外部へ飛ばしたい
- 内部リンクは可能な限りローカルHTMLへ向けたい
- query形式のURLは、できれば意味のある静的URLへ変換したい

まず、バックエンドで行うべき準備、クローリング方針、変換方針、検証方針をまとめてください。
```

## 2. クロール実行を依頼する

```text
このフォルダに、CMSサイトをクローリングして静的HTMLを作ってください。

要件:
- 出力先は site/ とする
- 既存のsite/がある場合は、必要に応じてバックアップしてから0から作り直す
- HTML、CSS、JS、画像、フォント、PDFなど表示に必要なものを取得する
- RSS/Atomは不要
- 外部サイトへのリンクはローカル化せず、外部URLのまま残す
- 内部リンクはローカルファイルへ変換する
- できるだけ階層ズレを起こさない
- base hrefの影響も確認する
- 完了後、リンク切れと外部読み込み依存を検査する
```

## 3. query URLを整理させる

```text
静的化後のサイトに __query/hash.html のような意味不明なURLが残っています。
これを可能な限り削除し、意味の通るURLへ変換してください。

方針:
- RSS/Atom由来のqueryページは削除
- CMSの外部リンクリダイレクトは、直接外部URLへリンクする
- ページネーションは /page/2.html のようなURLへ変換する
- 同じ内容のItemid違いなどは、既存のクリーンURLへ統合する
- 最終的に site/__query が不要になるようにする
- HTML内に __query という文字列が残らないようにする

変換後は以下を確認してください。
- Test-Path site\__query が False
- rg -n "__query" site が一致なし
- リンク切れが0件
- ブラウザ解決後のリンク異常が0件
```

## 4. 外部読み込み依存をなくす

```text
この静的サイトで、外部サイトへの通常リンク以外は、可能な限りすべてローカルファイルを参照する状態にしてください。

確認対象:
- CSS
- JS
- 画像
- Webフォント
- favicon
- 背景画像
- カルーセル画像
- パンくずリストの記号
- ロゴ
- analytics/tag manager/CDN

外部読み込みが必要ないものは削除してください。
必要なものはローカルへ保存して参照を書き換えてください。
最後に外部読み込み資源が0件であることを確認してください。
```

## 5. 表示が遅い箇所の調査

```text
静的化したサイトで、次の表示が遅いです。

- トップページのカルーセル
- ロゴ
- パンくずリストの記号
- フッターリンク前の記号

本当に外部リソースを読みに行っていないか確認してください。
Webフォント依存や、遅延ロード、Ajax、外部CDN、存在しない画像参照が残っていないか調べてください。

必要なら、記号はWebフォントではなく通常文字の > などに置き換えて構いません。
```

## 6. フォーム・メール・個人情報を消す

```text
静的HTML内から、ドメインメールアドレス、問い合わせフォーム、CMSのログイン/投稿/検索など、静的化後に不要または機能しないものを削除・無効化してください。

対象:
- mailto:
- 対象ドメインのメールアドレス
- <form>
- action= で外部またはCMSへ送信する箇所
- ログイン、検索、問い合わせ、コメント投稿

削除後、HTML全体を検索して残存がないか確認してください。
```

## 7. 最終確認を依頼する

```text
問題が残っていないか、静的サイト全体を最終確認してください。

確認してほしいこと:
- ローカルリンク切れ
- CSS/JS/画像/フォント/PDFの欠落
- ブラウザで解決されるURLの異常
- 外部読み込み依存
- Webフォント依存
- 表示に時間がかかるギミック
- query中間ページの残存
- フォームやメールアドレスの残存
- ページネーションのリンク切れ
- 代表ページの表示崩れ

可能ならローカルHTTPサーバーで配信し、HTTPレベルでも全リソースが200で取れるか確認してください。
結果は件数付きで報告してください。
```

## 8. GitHub Pagesへアップロードする

```text
この静的サイトをGitHub Pagesへ公開したいです。

条件:
- Organization: <organization-or-account>
- Repository: website
- 公開対象: site/ 以下
- カスタムドメイン: <domain>

gitリポジトリの初期化、commit、push、GitHub Pages設定、DNS設定まで、必要な手順を教えてください。
可能な範囲でこの環境から実行してください。
実行前にログインやpushが必要な場合は確認してください。
```

## 9. DNS確認を依頼する

```text
DNSが反映されたか確認してください。

確認対象:
- <domain> のAレコード
- www.<domain> のCNAME
- 1.1.1.1
- 8.8.8.8
- 権威DNS
- 現在の回線の既定DNS
- GitHub Pages IPに固定したHTTPS応答

古いホスティング先が返っている場合は、設定ミスかキャッシュ残りかを切り分けてください。
```
